# reestr-watch-bot

Простой бот: раз в 15 минут проверяет реестр Минюста
(`https://reestrs.minjust.gov.ru/#/registry/e102742c-8473-3be5-2a78-5927f0fba20f`)
через его собственный API и шлёт сообщение в Telegram, если реестр обновился.

Как это работает: у страницы реестра есть публичный API без авторизации.
`GET /rest/registry/{id}/info` отдаёт метку времени последнего изменения
(`lastModified`). Бот сравнивает её с прошлым значением; если она изменилась —
дополнительно забирает записи через `POST /rest/registry/{id}/values` и
присылает их в сообщении.

## Настройка Telegram

1. В Telegram напишите @BotFather → `/newbot` → следуйте подсказкам, получите
   `TELEGRAM_BOT_TOKEN` (выглядит как `123456:ABC-...`).
2. Напишите новому боту любое сообщение (например `/start`) — иначе он не
   сможет писать вам первым.
3. Узнайте свой `chat_id`: откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите в ответе
   `"chat":{"id":ЧИСЛО, ...}` — это и есть `TELEGRAM_CHAT_ID`.

## Локальный запуск (PyCharm или терминал) — сначала тут

Прежде чем тащить на Railway, проверьте, что бот вообще работает у вас
на компьютере.

1. Установите зависимость (в терминале PyCharm, или в обычном терминале
   внутри папки проекта):
   ```
   pip install "requests[socks]==2.32.3"
   ```
2. Задайте переменные окружения — **обязательно до первого запуска**,
   иначе сразу упадёт `KeyError`:
   - В PyCharm: правый клик по `Main.py` → **Run 'Main'** (один раз, чтобы
     конфигурация вообще появилась в списке) → она сразу упадёт с ошибкой,
     это нормально → сверху рядом с ▶ откройте выпадающий список →
     **Edit Configurations...** → поле **Environment variables** → добавьте:
     - `TELEGRAM_BOT_TOKEN` = ваш токен от BotFather
     - `TELEGRAM_CHAT_ID` = `20182974` (или ваш)
   - Или через терминал:
     ```
     TELEGRAM_BOT_TOKEN="ваш_токен" TELEGRAM_CHAT_ID="20182974" python Main.py
     ```
3. Запустите (▶ в PyCharm или командой выше). В консоли должно появиться
   что-то вроде:
   ```
   ... Старт. Интервал проверки: 900 сек. Прокси: выключен (прямое подключение)
   ... Инициализация, базовый lastModified=...
   ```
   а в Telegram от бота прилетит "✅ Бот-наблюдатель за реестром запущен."
   Если оба сообщения на месте — бот рабочий, можно останавливать
   (квадратная кнопка/Ctrl+C) и переходить к Railway.

   Хотите проверить не через 15 минут, а быстро — временно добавьте ещё
   одну переменную `CHECK_INTERVAL_SECONDS` = `30` на время локального
   теста (потом просто не переносите её на Railway, там останется дефолт
   15 минут).

   Состояние (`state.json`) при локальном запуске создаётся прямо рядом
   со скриптом — это нормально, отдельно ничего настраивать не нужно.

## Деплой на Railway

1. Новый проект → Deploy from GitHub repo (или `railway up` из этой папки).
2. Railway сам подхватит `requirements.txt` и `Procfile`
   (стартовая команда: `python main.py`; если попросит — укажите её вручную
   в Settings → Deploy → Start Command).
3. В Variables добавьте:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `CHECK_INTERVAL_SECONDS` — необязательно, по умолчанию 900 (15 минут)
   - `PROXY_URL` — **сначала не добавляйте вообще**, это первый тест
4. (опционально) По умолчанию файл состояния (`state.json`, последний
   известный `lastModified`) лежит прямо в контейнере и слетает при каждом
   передеплое — не страшно, бот просто один раз "переустановит" точку
   отсчёта без алерта. Если хочется, чтобы состояние переживало передеплои —
   добавьте в Railway Volume, примонтируйте на `/data`, и добавьте
   переменную `STATE_FILE` = `/data/state.json`.
5. Deploy. В логах должно появиться `Старт. Интервал проверки: 900 сек...`,
   а в Telegram — сообщение "✅ Бот-наблюдатель за реестром запущен."

## Наблюдение за обычными страницами (не реестрами)

Кроме реестров Минюста бот следит за страницами со списком ссылок. Сейчас
это страница судебной статистики Судебного департамента
(`https://cdep.ru/?id=79`): бот запоминает список наборов данных и сообщает,
что добавилось, что пропало и что переименовали.

Настраивается списком `PAGE_WATCHERS` в коде:

```python
{
    "key": "cdep_sudstat",        # под этим именем состояние лежит в state.json
    "title": "...",               # как называть страницу в сообщениях
    "url": "https://cdep.ru/?id=79",
    "selector": "div.contentBody.customArea a",   # CSS-селектор ссылок
    "encoding": "windows-1251",   # кодировка страницы, если сайт её не указывает
}
```

Две вещи, на которые тут стоит обратить внимание:

- **Кодировка.** cdep.ru отдаёт страницу в windows-1251 и не пишет об этом
  в заголовке. `requests` в таком случае угадывает latin-1, и русский текст
  превращается в мусор - поэтому кодировка задаётся явно.
- **Ключ записи.** У каждого набора в адресе свой номер (`?id=79&item=9291`),
  по нему бот и отличает наборы. Поэтому переименование видно как
  переименование, а не как «один удалили, другой добавили».

Проверка идёт **по расписанию**, а не каждые три минуты - данные там
полугодовые. Часы задаются переменной `PAGE_CHECK_HOURS` (по умолчанию
`9,14,22`) в часовом поясе `PAGE_CHECK_TZ` (по умолчанию `Europe/Berlin`,
то есть CET зимой и CEST летом). Пока назначенный час не сменился, повторных
заходов нет, так что перезапуск бота лишних запросов не делает.

Если по селектору не нашлось ни одной ссылки, бот считает это поломкой
(сменилась вёрстка или приехала заглушка) и ругается в Telegram, а не
рассылает «все наборы удалены».

### Тип `table_tail` — хвост постраничной таблицы

Так устроен федеральный список экстремистских материалов
(`minjust.gov.ru/ru/extremist-materials/`): таблица на ~5500 пунктов,
разбитая по 100 штук на страницу, всего 55 страниц. Новые пункты всегда
дописываются в конец, поэтому бот берёт только последнюю страницу: сначала
первую (узнать, сколько всего страниц), потом последнюю — два запроса
вместо пятидесяти пяти.

Сообщение про новый пункт выглядит так:

```
➕ НОВЫЙ МАТЕРИАЛ №5513
Внесён в список: 4 сентября 2026
Решение: Пензенского областного суда от 15.07.2026

<полное описание, как на сайте, без сокращений>
```

Описание никогда не обрезается: медиана ~380 символов, максимум ~715, в
лимит Telegram влезает с запасом. Режим сводки (который для реестров
включается при 40+ изменениях) для таблиц отключён намеренно.

Строка «Решение» — это первое решение суда, выдернутое из описания
регуляркой. Апелляции и кассации в неё не выносятся, они остаются внутри
описания. Если формат не распознался, строки просто не будет.

### Тип `table_all` — вся таблица с одной страницы

Так устроен единый федеральный список террористических организаций ФСБ
(`http://www.fsb.ru/fsb/npd/terror.htm`) — 77 организаций на одной странице,
без постраничной навигации. Поэтому тут, в отличие от `table_tail`, честно
ловятся и новые пункты, и исключения, и правки в существующих.

**Главная ловушка этой страницы — вёрстка.** Пункты 1-72 лежат в одной
большой таблице, а каждый следующий добавлен ОТДЕЛЬНОЙ таблицей на одну
строку: судя по всему, новый кусок вёрстки дописывают руками. Если брать
«самую большую таблицу», бот не увидит ни нынешние 73-77, ни одно будущее
пополнение — а именно пополнения тут и интересны. Поэтому разбираются
строки **всех** таблиц страницы, у которых в первой ячейке номер.

Второе: сайт работает только по http и на https отвечает редиректом обратно
на http. Браузеры показывают «This site doesn't support a secure connection»
и требуют подтверждения, а `requests` сходит по http без возражений — для
бота это не препятствие.

Сообщение:

```
➕ НОВАЯ ОРГАНИЗАЦИЯ №78
Движение «Тестовое объединение»

Решение: Верховный Суд Российской Федерации, от 01.09.2026 № АКПИ26-100с,
вступило в силу 15.09.2026
```

**Чего тип `table_tail` НЕ ловит: исключений из списка.** Видно только последнюю
страницу, поэтому «пункт исключили» и «пункт уехал за пределы нашего окна»
неотличимы. Отдельно опасен момент, когда последняя страница заполняется
и начинается следующая: из окна разом выпадают все 100 пунктов прежней.
Поэтому исключения не отслеживаются вовсе — иначе бот при каждом переходе
на новую страницу рассылал бы «исключено 100 материалов». Чтобы ловить
исключения по-настоящему, нужен полный обход всех страниц.

## Важно про API: потолок в 1000 записей

`POST /rest/registry/{id}/values` отдаёт **максимум 1000 строк за запрос**,
какой бы `limit` ни просили (проверено: `limit=2000` и `limit=5000` оба
возвращают ровно 1000 при `size=1257`). Причём молча, без ошибки.

Поэтому бот забирает записи страницами по 1000 через `offset`, пока не
выберет все `size` строк. Без этого всё, что в реестре после тысячной
строки, для бота не существует - а новые записи дописываются как раз
в конец, то есть именно они и терялись.

Общий предохранитель - `MAX_ROWS` (по умолчанию 20000), чтобы случайно не
начать тянуть реестр адвокатов на 157 тысяч строк.

## Подписка по паролю

Чтобы не добывать `chat_id` руками для каждого нового человека, бот умеет
принимать подписки сам: человек пишет ему `/start`, бот просит пароль,
человек присылает пароль - и начинает получать уведомления.

Включается переменной `ACCESS_PASSWORD` на Railway. Нет переменной -
механизм выключен совсем, и бот ни на что не отвечает, как раньше.

Команды: `/start` и `/help` - что это за бот, `/stop` - отписаться,
`/who` - список подписчиков (только для постоянных получателей).

**Обязательно подключите Volume**, иначе подписчики будут теряться при
каждом передеплое: Railway → Volumes → New Volume, точка монтирования
`/data`, затем переменная `STATE_FILE=/data/state.json`. Вписанные в код
`EXTRA_CHAT_IDS` и переменная `TELEGRAM_CHAT_ID` - постоянная основа,
они не теряются никогда; подписавшиеся по паролю живут в файле состояния.

Защита от подбора: `PASSWORD_ATTEMPTS` неверных попыток (по умолчанию 5),
потом бот перестаёт отвечать этому человеку на `PASSWORD_LOCKOUT_SECONDS`
(по умолчанию час). Блокировка временная намеренно - иначе человек,
опечатавшийся пять раз, не смог бы подписаться уже никогда.

О каждой подписке, отписке и исчерпании попыток бот сообщает постоянным
получателям - чтобы не было тихо подключившихся читателей.

Пауза между проверками реестров проходит не во сне, а на длинном опросе
Telegram, поэтому ответ на `/start` приходит за секунду. Важно: `getUpdates`
отдаёт входящие только ОДНОМУ слушателю, так что не запускайте бота локально,
пока он крутится на Railway - иначе оба будут ловить ошибку 409.

## Несколько получателей

`TELEGRAM_CHAT_ID` можно указать не один chat_id, а несколько через запятую -
все они получат одно и то же сообщение (формат как у `REGISTRY_IDS`):

```
TELEGRAM_CHAT_ID = 20182974, 987654321
```

Чтобы узнать chat_id друга:

1. Друг находит вашего бота в Telegram (по имени `@minskojust_bot`) и
   отправляет ему любое сообщение, например `/start`. Больше от него ничего
   не требуется.
2. Вы открываете в браузере (подставив свой токен):
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
3. В ответе ищете самую свежую запись с `"chat":{"id":ЧИСЛО, ...}`,
   стоящую рядом с именем/username друга, - это его chat_id.
4. В Railway → Variables → `TELEGRAM_CHAT_ID` дописываете этот chat_id через
   запятую к уже имеющемуся своему.
5. Сохраняете - Railway передеплоит сам (или жмите Deploy вручную, если не
   началось само).

## Если реестр не отвечает (геоблок)

Если в логах Railway видите таймауты/ошибки подключения к
`reestrs.minjust.gov.ru`, а с вашего компьютера сайт открывается — похоже,
сайт действительно режет не-российские IP (Railway хостится не в РФ).

В этом случае самый простой фикс — не пытаться городить свой VPN-туннель
внутри контейнера (Railway, как и большинство PaaS, не даёт контейнеру
поднимать TUN-интерфейс, так что штатный `.ovpn`/WireGuard-конфиг там
не заведётся), а взять готовый **российский datacenter-прокси** (HTTP или
SOCKS5) у любого прокси-провайдера — это буквально `host:port` + логин/
пароль, стоит от 1-2$/мес. Впишите его в переменную `PROXY_URL` в формате:

```
http://user:pass@host:port
```

или

```
socks5://user:pass@host:port
```

и передеплойте — код уже готов это подхватить, без правок.
