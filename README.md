# reestr-watch-bot

Простой бот: раз в 15 минут проверяет реестр Минюста
(`https://reestrs.minjust.gov.ru/#/registry/e102742c-8473-3be5-2a78-5927f0fba20f`)
через его собственный API и шлёт сообщение в Telegram, если реестр обновился.

Как это работает: у страницы реестра есть публичный API без авторизации.
`GET /rest/registry/{id}/info` отдаёт метку времени последнего изменения
(`lastModified`). Бот сравнивает её с прошлым значением; если она изменилась —
дополнительно забирает записи через `POST /rest/registry/{id}/values` и
присылает их в сообщении.

## Настройка Telegram

1. В Telegram напишите @BotFather → `/newbot` → следуйте подсказкам, получите
   `TELEGRAM_BOT_TOKEN` (выглядит как `123456:ABC-...`).
2. Напишите новому боту любое сообщение (например `/start`) — иначе он не
   сможет писать вам первым.
3. Узнайте свой `chat_id`: откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите в ответе
   `"chat":{"id":ЧИСЛО, ...}` — это и есть `TELEGRAM_CHAT_ID`.

## Локальный запуск (PyCharm или терминал) — сначала тут

Прежде чем тащить на Railway, проверьте, что бот вообще работает у вас
на компьютере.

1. Установите зависимость (в терминале PyCharm, или в обычном терминале
   внутри папки проекта):
   ```
   pip install "requests[socks]==2.32.3"
   ```
2. Задайте переменные окружения — **обязательно до первого запуска**,
   иначе сразу упадёт `KeyError`:
   - В PyCharm: правый клик по `Main.py` → **Run 'Main'** (один раз, чтобы
     конфигурация вообще появилась в списке) → она сразу упадёт с ошибкой,
     это нормально → сверху рядом с ▶ откройте выпадающий список →
     **Edit Configurations...** → поле **Environment variables** → добавьте:
     - `TELEGRAM_BOT_TOKEN` = ваш токен от BotFather
     - `TELEGRAM_CHAT_ID` = `20182974` (или ваш)
   - Или через терминал:
     ```
     TELEGRAM_BOT_TOKEN="ваш_токен" TELEGRAM_CHAT_ID="20182974" python Main.py
     ```
3. Запустите (▶ в PyCharm или командой выше). В консоли должно появиться
   что-то вроде:
   ```
   ... Старт. Интервал проверки: 900 сек. Прокси: выключен (прямое подключение)
   ... Инициализация, базовый lastModified=...
   ```
   а в Telegram от бота прилетит "✅ Бот-наблюдатель за реестром запущен."
   Если оба сообщения на месте — бот рабочий, можно останавливать
   (квадратная кнопка/Ctrl+C) и переходить к Railway.

   Хотите проверить не через 15 минут, а быстро — временно добавьте ещё
   одну переменную `CHECK_INTERVAL_SECONDS` = `30` на время локального
   теста (потом просто не переносите её на Railway, там останется дефолт
   15 минут).

   Состояние (`state.json`) при локальном запуске создаётся прямо рядом
   со скриптом — это нормально, отдельно ничего настраивать не нужно.

## Деплой на Railway

1. Новый проект → Deploy from GitHub repo (или `railway up` из этой папки).
2. Railway сам подхватит `requirements.txt` и `Procfile`
   (стартовая команда: `python main.py`; если попросит — укажите её вручную
   в Settings → Deploy → Start Command).
3. В Variables добавьте:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `CHECK_INTERVAL_SECONDS` — необязательно, по умолчанию 900 (15 минут)
   - `PROXY_URL` — **сначала не добавляйте вообще**, это первый тест
4. (опционально) По умолчанию файл состояния (`state.json`, последний
   известный `lastModified`) лежит прямо в контейнере и слетает при каждом
   передеплое — не страшно, бот просто один раз "переустановит" точку
   отсчёта без алерта. Если хочется, чтобы состояние переживало передеплои —
   добавьте в Railway Volume, примонтируйте на `/data`, и добавьте
   переменную `STATE_FILE` = `/data/state.json`.
5. Deploy. В логах должно появиться `Старт. Интервал проверки: 900 сек...`,
   а в Telegram — сообщение "✅ Бот-наблюдатель за реестром запущен."

## Если реестр не отвечает (геоблок)

Если в логах Railway видите таймауты/ошибки подключения к
`reestrs.minjust.gov.ru`, а с вашего компьютера сайт открывается — похоже,
сайт действительно режет не-российские IP (Railway хостится не в РФ).

В этом случае самый простой фикс — не пытаться городить свой VPN-туннель
внутри контейнера (Railway, как и большинство PaaS, не даёт контейнеру
поднимать TUN-интерфейс, так что штатный `.ovpn`/WireGuard-конфиг там
не заведётся), а взять готовый **российский datacenter-прокси** (HTTP или
SOCKS5) у любого прокси-провайдера — это буквально `host:port` + логин/
пароль, стоит от 1-2$/мес. Впишите его в переменную `PROXY_URL` в формате:

```
http://user:pass@host:port
```

или

```
socks5://user:pass@host:port
```

и передеплойте — код уже готов это подхватить, без правок.
